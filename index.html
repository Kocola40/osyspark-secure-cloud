01 · Le contexte

Une architecture pensée pour une startup en croissance.

Le point de départ : un cahier des charges pédagogique présentant une startup fictive qui passe de 8 à 20 collaborateurs, avec des besoins de collaboration, de réseau, de sauvegarde et de sécurité.

◈
01 / Diagnostiquer

Comprendre le risque

Inventaire des actifs fictifs, menaces prioritaires, dépendances métier et exigences de sécurité documentées.

◇
02 / Concevoir

Sécuriser par défaut

Segmentation réseau, accès minimaux, SSO/MFA, durcissement et gestion de la configuration.

◎
03 / Démontrer

Prouver le résultat

Tests reproductibles, journaux, captures d'écran, restauration et comptes rendus de validation.

Transparence : ce portfolio décrit un projet académique et un laboratoire de test. Il ne prétend pas qu'une entreprise réelle a été auditée ou que tous les composants sont déjà opérationnels.

02 · Architecture

Deux vues, un même objectif.

Une vue fonctionnelle pour expliquer les protections d'une startup et une vue laboratoire pour les expérimenter sans cloud payant ni matériel supplémentaire.

Vue cible · Cas d'usage startup fictive

Modèle de sécurité défini par les besoins : accès utilisateurs, applications internes, réseau administré, détection et sauvegardes. Ce schéma illustre une conception et non une infrastructure de production installée.

👥 Utilisateurs / postesComptes, appareils, accès distant, politique MFA
🔑 Identité / collaborationKeycloak (SSO) · Nextcloud (fichiers) en laboratoire
↕   Contrôles d'accès   ↕
🛡️ OPNsense — pare-feu, VPN et filtrage inter-VLANPolitique « deny by default » entre zones sensibles
VLAN 10Postes utilisateurs
VLAN 20Applications internes
VLAN 30Administration
🔎 Wazuh / SuricataCollecte, alertes, investigation et journalisation
💾 Sauvegardes / repriseCopies séparées, tests de restauration et runbooks
Hypothèse : un VLAN 40 de tests isolé est prévu dans le laboratoire, sans accès au réseau domestique ou à un système tiers.
Vue réalisation · Sur matériel déjà possédé

Un ordinateur existant, un hyperviseur et des réseaux purement virtuels. Aucun équipement réseau physique supplémentaire n'est requis pour tester les règles de filtrage.

🖥️ Machine hôte existante · Proxmox VE / hyperviseur compatibleRessources conseillées pour une exécution simultanée : 32 Go de RAM ; sous 16 Go, procéder par étapes

À prévoir : snapshots, configuration reproductible, absence d'exposition directe d'interfaces d'administration sur Internet et sauvegarde locale ou sur support déjà disponible.

05 · Validation

Huit démonstrations reproductibles.

Les protocoles sont prévus, mais aucun résultat n'est déclaré réussi tant qu'une preuve vérifiable n'a pas été produite.

T01 · Filtrage inter-VLAN

À tester

Un client invité ne doit pas joindre le segment d'administration.

Preuve : règle + connexion refusée

T02 · Accès autorisé

À tester

Un flux métier explicitement permis traverse le pare-feu.

Preuve : règle + test positif

T03 · MFA / authentification

À tester

Un compte de test doit satisfaire la politique d'authentification.

Preuve : politiques + journaux

T04 · Moindre privilège

À tester

Un utilisateur standard ne peut pas gérer les comptes administrateurs.

Preuve : matrice RBAC + refus

T05 · Alerte SOC

À tester

Une série d'échecs de connexion sur VM de test génère une alerte.

Preuve : événements Wazuh

T06 · Détection réseau

À tester

Suricata remonte un événement créé sur le trafic du laboratoire.

Preuve : règle + journal IDS

T07 · Restauration

À tester

Restaurer un fichier fictif après suppression volontaire.

Preuve : empreinte + temps mesuré

T08 · Reproductibilité

À tester

Recréer une configuration avec un script versionné.

Preuve : script + exécution

Espace réservé aux preuves

Ces emplacements seront remplacés par tes captures réelles, tableaux de résultats et liens vers les procédures.

06 · Budget

Zéro achat, pas zéro contrainte.

L'objectif est de ne déclencher aucune dépense supplémentaire pour le laboratoire et la publication du portfolio.

Dépenses monétaires supplémentaires prévues
0 €

Hébergement GitHub Pages gratuit, solutions open source et utilisation d'un ordinateur déjà disponible.
